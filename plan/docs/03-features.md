# 03 — Feature Catalog

Each feature has an ID (`F-xx`), a priority label (**MVP** / **Stretch** / **Later**) and acceptance criteria (AC). The detailed behaviour lives in the linked docs, and this page is the index of *what* gets built.

## F-01 Indexing & graph (engine)

| ID | Feature | Priority | Spec |
|---|---|---|---|
| F-01.1 | **Scanner**: walk the project, respect `.gitignore` + `.catalystignore` + built-in ignores, detect language per file, hash contents | MVP | [06 §1](06-analysis-pipeline.md) |
| F-01.2 | **Tier 1 parsing (TS/JS/TSX/JSX)**: definitions, imports/exports, calls, JSX renders, classes/methods | MVP | [06 §2](06-analysis-pipeline.md) |
| F-01.3 | **Tier 1 parsing (Python)**: definitions, imports, calls, classes/methods, decorators | MVP | [06 §2](06-analysis-pipeline.md) |
| F-01.4 | **Import resolution**: TS relative/index/extension, `tsconfig`/`jsconfig` `paths` + `baseUrl`, workspace packages, bare specifiers to external packages; Python absolute/relative/`src` layout | MVP | [06 §3](06-analysis-pipeline.md) |
| F-01.5 | **Call resolution**: local scope, then import bindings, then a unique-name heuristic | MVP | [06 §3](06-analysis-pipeline.md) |
| F-01.6 | **Framework detectors**: routes (Next.js app/pages, Express/Hono/Fastify, FastAPI/Flask), DB models + read/write ops (Prisma, Supabase, SQLAlchemy/SQLModel), env vars, external services (Stripe, auth libs, email, AI SDKs, cloud SDKs), React components | MVP (core set) / Stretch (Drizzle, Django, tRPC, Mongoose) | [06 §4](06-analysis-pipeline.md) |
| F-01.7 | **Tier 2 languages**: tree-sitter `tags` queries for Go/Rust/Java/Ruby/C#/PHP, name-matched edges | Later (Go: Stretch) | [06 §2.3](06-analysis-pipeline.md) |
| F-01.8 | **Tier 3 LLM extraction**: LLM returns symbols and edges for unsupported files (SQL, YAML, config, other languages) | Stretch | [06 §5.6](06-analysis-pipeline.md) |
| F-01.9 | **Incremental re-index**: only changed files (by hash) are re-parsed, and only affected summaries are regenerated | MVP (on re-run) | [06 §6](06-analysis-pipeline.md) |
| F-01.10 | **Watch mode**: re-index on file save while serving | Later | [06 §6](06-analysis-pipeline.md) |
| F-01.11 | **Graph algorithms**: SCC/cycles, Louvain communities, fan-in/out, BFS impact | MVP | [06 §4.5](06-analysis-pipeline.md), [11](11-health-analysis.md) |

**AC (MVP):** indexing `taxonomy` produces file, symbol, route, DB model, env and external service nodes. More than 90% of relative and alias imports resolve. Re-running with no changes performs zero parses and makes zero LLM calls.

## F-02 Understanding (AI pipeline)

| ID | Feature | Priority | Spec |
|---|---|---|---|
| F-02.1 | **File summaries**: structured, plain-English summaries per file (purpose, role, side effects, tags, key symbols), generated by the cheap model with graph context | MVP | [06 §5.2](06-analysis-pipeline.md) |
| F-02.2 | **Symbol summaries**: one-liners for important symbols (exported, high fan-in, route handlers), included in the file summary call | MVP | [06 §5.2](06-analysis-pipeline.md) |
| F-02.3 | **Module roll-ups**: directory summaries built from their children's summaries | MVP | [06 §5.3](06-analysis-pipeline.md) |
| F-02.4 | **Feature discovery**: the strong model groups the code into Features with members, entry points and dependencies | MVP | [06 §5.4](06-analysis-pipeline.md) |
| F-02.5 | **Flows**: ordered steps per feature (entry → … → data/external), validated against graph paths | MVP (list) | [06 §5.4](06-analysis-pipeline.md) |
| F-02.6 | **App overview**: what the app is, who it is for, the stack, the features and how they connect | MVP | [06 §5.5](06-analysis-pipeline.md) |
| F-02.7 | **Changeability cards**: per feature, how hard it is to add to, modify or remove, citing metrics | MVP | [11 §4](11-health-analysis.md) |
| F-02.8 | **Output language** `en`/`tr` for all AI-written text | Stretch | [07 §6](07-llm-providers.md) |
| F-02.9 | **Cost estimate + budget cap** before the AI stages run | Stretch (MVP: file count + "this will make ~N calls") | [07 §5](07-llm-providers.md) |
| F-02.10 | **Structural-only mode** when no AI is configured (graph, search over code, health flags) | MVP (free by-product) | [07 §1](07-llm-providers.md) |

**AC (MVP):** every file has a summary. Features have at least 1 entry point and at least 2 members. Every node ID that the LLM cites exists in the graph; invalid IDs are dropped before saving.

## F-04 Search & Ask

| ID | Feature | Priority | Spec |
|---|---|---|---|
| F-04.1 | **Find**: instant fuzzy search over symbol, file and route names | MVP | [08](08-api.md), [10 §3.7](10-web-ui.md) |
| F-04.2 | **Search**: SQLite FTS5 over names, paths, summaries, tags and code snippets | MVP | [05 §4](05-data-model.md) |

| F-04.4 | Ask history per project | Stretch | [05](05-data-model.md) |
| F-04.5 | Structured graph filters (edge kind, feature, node kind, provenance) | MVP (basic) | [10 §3.6](10-web-ui.md) |

**AC (MVP):** "stripe webhook" returns the webhook route in the top 3 results. Ask answers cite at least one node, and every citation is clickable. Asking about a missing feature returns `found: false` together with the list of searches made.
